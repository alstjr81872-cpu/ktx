# 빈자리

혼자 사용하는 코레일 좌석 알림 웹앱입니다. 역·날짜·시간대·열차·좌석 등급을 선택하면 서버에서 반복 조회하고, 빈자리를 찾으면 화면과 소리, 허용한 브라우저 알림으로 알려줍니다. 예매는 사용자가 코레일에서 직접 진행합니다.

## 실행

### Render에서 웹주소 만들기

[Render에 배포](https://render.com/deploy?repo=https://github.com/alstjr81872-cpu/ktx)

1. 위 링크로 Render에 로그인하고 GitHub의 `alstjr81872-cpu/ktx` 저장소 접근을 허용합니다. 비공개 저장소라면 Render 대시보드 → New → Blueprint에서 저장소를 선택할 수도 있습니다.
2. `render.yaml`의 `binjari` 서비스를 확인하고 배포합니다. 무료 플랜과 싱가포르 리전이 기본값입니다.
3. 배포가 `Live`가 되면 서비스 화면의 `https://…onrender.com` 주소를 엽니다. 이 주소가 어디서든 접속하는 실제 웹주소입니다. 이름 중복에 따라 주소가 달라지므로 Render에서 발급된 주소를 사용하세요.
4. 먼저 ‘체험해 보기’로 알림을 확인한 뒤 실제 탐색을 시작합니다. 클라우드 서버에서 코레일 연결이 제한되면 화면에 오류가 표시됩니다. 앱 상태 검사 성공만으로 코레일 연결까지 보장하지 않습니다.

`Dockerfile`이 Node.js와 Python 의존성을 함께 설치합니다. Render가 HTTPS를 제공하며, `PORT` 환경변수로 지정한 포트에서 서버가 실행됩니다. SSE 연결과 메모리 탐색 상태를 위해 인스턴스는 하나로 유지하세요.

무료 서비스는 유휴 시 절전되므로 첫 접속이 늦어질 수 있습니다. 재시작·재배포 시 서버 메모리와 기기 식별자가 초기화됩니다. 창을 열어두면 브라우저에 저장한 조건으로 탐색을 자동 복구합니다. 항상 실행하려면 Render에서 유료 플랜을 선택할 수 있습니다. 유료 디스크를 연결할 경우 `KORAIL_STATE_FILE`을 해당 마운트 경로 아래로 지정하면 기기 식별자를 보존할 수 있습니다.

현재는 로그인 없는 개인용 단일 탐색 앱입니다. 주소에 접근하는 다른 사람도 탐색을 시작할 수 있으므로 링크를 공개 공유하지 마세요. 여러 기기에서 동시에 서로 다른 탐색을 실행하는 용도는 지원하지 않습니다.

Docker로 동일 구성을 실행하려면:

```bash
docker build -t binjari .
docker run --rm -p 10000:10000 binjari
```

### 로컬 실행

Node.js 20.9 이상과 Python 3.10 이상이 필요합니다. 이 환경에서는 Node.js 24와 Python 3.12로 검증했습니다.

```bash
cd /workspace/ktx
npm ci --cache /workspace/.npm-cache
npm run setup:korail
npm run dev
```

기본 포트는 3000입니다. 운영 모드는 다음과 같습니다.

```bash
npm run build
npm run start
```

`npm run dev`와 `npm run start`는 각각 장시간 실행하는 서버 명령입니다. 같은 포트에서 동시에 실행하지 않습니다. 개발용 클라우드에서는 기존 `/workspace/ktx` 체크아웃을 사용하세요. 새 Git worktree가 필요하지 않습니다.

## 검증된 실제 좌석 조회

- 코레일의 현재 요청 형식에 맞춰 `pykorail==0.2.1`의 서명·HTTPS 전송 계층을 연결했습니다. 과거의 서명 없는 GET 요청을 현재의 서명 포함 POST 요청으로 교체했습니다.
- **로그인 없이 실제 서울→부산 KTX 시간표와 일반실·특실 좌석 상태를 조회했습니다.** 실제 데이터와 체험 데이터는 구분하며, 실제 요청 실패를 체험 결과로 바꾸지 않습니다.
- 브라우저 검증은 실제 모드에서 2초 간격의 연속 조회와 좌석 발견 팝업을 확인합니다. 좌석 상태는 실시간으로 바뀌므로 검증 결과의 ‘좌석 있음’이 이후에도 유지된다는 뜻은 아닙니다.
- 타입 검사, 프로덕션 빌드, Node 테스트 23개, Python 테스트 3개, 체험 모드의 데스크톱·모바일 UI 흐름도 검증합니다.
- 앱은 로그인·예매 API를 호출하지 않습니다. 코레일 회원번호·비밀번호·사용자 토큰이 필요하지 않습니다.
- 외부 연결은 `smart.letskorail.com`으로만 전송합니다. 401/403 또는 `MACRO ERROR`가 발생하면 탐색을 일시정지하며, 429와 일시적인 연결 오류에는 간격을 늘려 재시도합니다.

## 연결 모듈과 재설치

`npm run setup:korail`은 프로젝트의 `.venv`에 고정된 Python 의존성을 설치합니다. `requirements-korail.lock`에 모든 의존성 버전과 PyPI SHA-256을 기록했고, 설치할 때 `--require-hashes`와 `--only-binary=:all:`을 사용합니다. 이 명령은 재실행할 수 있습니다.

조회 서버는 Python 작업 프로세스 하나를 유지하고 매번 새 요청 서명을 만듭니다. 앱의 기기 식별자는 `.local/korail-device.json`에 한 번 생성하여 재시작 후에도 재사용합니다. 이 폴더와 가상환경은 Git에서 제외하고 Next.js 빌드에도 포함하지 않습니다. 기존 식별자 파일을 자동으로 덮어쓰지 않습니다.

기본 Python 실행 파일은 `.venv/bin/python`(Windows는 `.venv/Scripts/python.exe`)입니다. 다른 실행 파일이 필요하면 `KORAIL_PYTHON`, 설치에 사용할 Python은 `KORAIL_BOOTSTRAP_PYTHON`으로 지정할 수 있습니다. 상태 파일 위치는 `KORAIL_STATE_FILE`로 지정할 수 있습니다. 기본 환경에서는 추가 변수가 필요하지 않습니다.

Python 프로세스 경로 추적에 관한 Turbopack 오류를 피하기 위해 개발과 빌드에 Next.js가 지원하는 Webpack 옵션을 사용합니다. Python 모듈은 프런트엔드 번들 밖에서 설치·실행됩니다.

## 사용하는 방법

1. 출발역과 도착역을 입력합니다. 초성 검색과 역 교환을 지원하며 목록에 없는 역도 직접 입력할 수 있습니다.
2. 출발 날짜, 성인 인원, 열차 종류, 최대 6시간의 출발 시간대, 일반실/특실을 고릅니다. 모든 시각은 한국시간 기준입니다.
3. 조회 간격은 **2·3·5·10·30초**, 기본값은 **3초**입니다. 현재 조회가 끝난 시점부터 다음 간격을 계산합니다. 시간 범위에 따라 한 번의 조회에서 여러 페이지를 읽을 수 있어 실제 탐색 주기는 요청 처리 시간만큼 길어집니다.
4. 소리 테스트를 해 보고, 필요하면 브라우저 알림을 허용합니다. 브라우저 알림은 HTTPS 또는 로컬 보안 컨텍스트와 브라우저 지원이 필요합니다.
5. ‘빈자리 탐색 시작’을 누른 뒤 창을 열어두세요. 빈자리가 나오면 코레일 버튼으로 이동해 같은 날짜·구간·열차를 찾아 예매합니다. 이 버튼은 코레일 홈페이지를 열며 검색 조건 자동 입력이나 좌석 확보를 하지 않습니다.
6. 일시정지 후 같은 조건으로 다시 시작할 수 있습니다. 조건 변경은 탐색을 종료한 후 가능합니다.

‘체험해 보기’는 현재 조건으로 가상 열차를 표시합니다. 세 번째 조회에 첫 열차의 좌석이 열립니다. 실제 탐색 버튼을 누르면 항상 실제 코레일 모드로 시작합니다.

## 탐색과 알림의 동작

- 서버의 단일 탐색 세션이 조회하고 SSE로 브라우저에 결과를 보냅니다. 다른 탭으로 이동해도 연결이 유지되면 탐색합니다.
- 연결이 잠시 끊겨도 탐색을 종료하지 않고 설정한 출발 시간대 끝까지 조회합니다. 브라우저는 20초마다 별도 상태 요청을 보내며 SSE 재연결과 인터넷 연결 복구도 감지합니다. 서버 재시작으로 세션이 사라지면 같은 ID와 조건으로 자동 복구합니다. 일시정지는 복구 후에도 유지하고, 사용자가 종료한 탐색은 복구하지 않습니다. 창을 닫거나 절전 중에는 알림을 받거나 서버 재시작 후 복구할 수 없으므로 탐색 창을 열어두세요.
- 새로고침하면 브라우저에 저장한 세션 ID로 기존 탐색을 이어받습니다. 소리는 브라우저 정책 때문에 다시 사용자 클릭이 필요할 수 있으므로 소리 테스트를 눌러 주세요.
- 처음부터 빈 좌석도 알립니다. 동일 열차·좌석 등급이 계속 비어 있으면 재알림하지 않고, 매진 후 다시 생기면 새 알림을 보냅니다. 오류 응답은 이전 좌석 상태를 유지하고 오류로 표시합니다.
- 실패 시 10·20·40·80·120초로 재시도 간격을 늘립니다. 접근 차단이나 로그인 요구 등 계속 반복해도 해결되지 않는 오류는 일시정지합니다. 성공하면 선택한 간격으로 돌아갑니다.
- 출발 시간 범위의 마지막 분이 지나면 탐색을 종료합니다. 알림 기록은 서버 메모리에 최대 50건, 화면 목록에는 최근 5건을 표시합니다.
- 이 앱은 장시간 실행하는 **단일 Node.js 프로세스**용입니다. 하나의 탐색을 허용하며 여러 브라우저 탭이 같은 세션을 볼 수 있습니다. 서버 재시작 시 결과·알림 이력은 초기화되지만 연결된 브라우저가 탐색 조건과 실행·일시정지 상태를 복구합니다. 서버리스 함수나 여러 서버 인스턴스로 배포하려면 별도 영속 저장소·작업 큐가 필요합니다.
- 로그인 기능이 없는 개인용 앱입니다. 본인만 접근할 수 있는 환경에서 실행하세요. 코레일 계정·비밀번호는 받거나 저장하지 않습니다.

## 개발과 검증

```bash
npm run typecheck
npm test
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
npm run build
```

브라우저 검증은 실행 중인 앱과 Chromium이 필요합니다. 현재 환경에는 `/usr/bin/chromium`이 있습니다.

```bash
# 별도 터미널에서 앱을 실행한 상태
npm run test:browser
# 별도 테스트 서버를 실행·강제 종료하며 자동 복구/일시정지/종료를 검증
npx tsx scripts/recovery-check.ts
# 다른 환경에서는 경로/주소 지정 가능
CHROMIUM_PATH=/path/to/chromium TEST_BASE_URL=http://127.0.0.1:3000 npm run test:browser
```

브라우저 검증은 체험 세션을 만들고 종료합니다. 실행 중인 개인 탐색이 없는 상태에서 사용하세요. 스크린샷은 `/tmp/binjari-check`에 저장합니다. `/api/health`는 웹 서버의 상태만 확인하며 코레일 연결 성공을 의미하지 않습니다.

실제 코레일 요청은 일반 테스트에 포함되지 않습니다. 필요할 때 명시적으로 실행하세요.

```bash
# 로그인이나 예매 없이 내일 서울→부산 KTX를 한 차례 조회
npm run check:live
# 실행 중인 앱에서 2초 간격으로 3회 조회하고 화면 알림 검증 후 종료
npm run test:live
```

`test:live`는 `/tmp/binjari-check/live-results.png`, 좌석이 발견되면 `live-alert.png`, 그리고 `live-result.json`을 남깁니다. 이 기록에는 요청 서명이나 기기 식별자가 포함되지 않습니다. 현재 코레일 API가 성공하더라도 향후 서버 변경이나 요청 제한이 생길 수 있으며, 그런 응답은 오류로 표시합니다.

## 주요 코드

- `components/seat-watch.tsx`: 검색 폼, 탐색 현황, 브라우저 저장, 소리·화면 알림
- `lib/config.ts`: 한국시간 기준 날짜·시간·간격 검증
- `lib/provider.ts`: 실제 좌석 응답 해석, 경계 시각을 겹쳐 읽는 페이지 조회, 체험 제공자
- `lib/korail-bridge.ts`: Node→Python 통신, 요청 취소·시간 초과·오류 처리
- `scripts/korail-worker.py`: 현재 코레일 요청 서명·전송, 조회 API만 제공
- `lib/monitor.ts`: 중복 없는 조회 루프, 재시도, 알림 변화 감지, 세션 수명
- `app/api/monitor`: 탐색 시작·제어·SSE API
- `tests/core.test.ts`: 조건 검증, 응답 해석, 페이지 조회, 중복 알림, 동시 조회 방지, 만료 테스트

외부 통신은 [pykorail 0.2.1](https://github.com/devgyurak/pykorail/releases/tag/v0.2.1)의 전송 계층을 사용해 현재 환경의 HTTP(S) 프록시 설정을 따르며 TLS 검증을 유지합니다. 별도 프록시 자격증명을 코드에 넣지 않습니다. 좌석 상태 해석은 [korail2](https://github.com/carpedm20/korail2)의 공개 프로토콜 설명도 참고했습니다. 이 프로젝트는 코레일 공식 서비스가 아닙니다.
